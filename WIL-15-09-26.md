ACK of the producer
how does it works -> when a event is received in the broker or it fails to reach a broker then what broker should do defines the ACK of the producer.

values that can be passed to the producer ACK
0 - fire and forget.
1 - waits till the leader broker reads the message, if the replicas fail to read the message it is silently ommitted.
all - waits untill all the replicas read the message.

Idempotent Producer - When an event is fired two times, due to network issue but the broker processed the message at the first hit, the second hit becomes idempotent.

By default from the version-3.0 kafka made this into a default behaviour

To enable/disable this `enable.idempotence = false`

difference between the kafka storing the logs and the applications logs
Kafka's logs store the data after it successfully arrives.
Application logs (from the callback) tell you if the data failed to arrive in the first place.
