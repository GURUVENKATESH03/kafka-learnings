## What I learned

### 1. Kafka and Spring Boot integration basics
- Kafka producers and consumers can be connected with Spring Kafka in a clean, Java-based setup.
- Sending messages is done through `KafkaTemplate`, while consumers are handled with `@KafkaListener`.
- A Kafka topic acts as the communication channel between producer and consumer services.

### 2. Error handling in Kafka consumers
- Consumer failures should be controlled centrally using a `DefaultErrorHandler`.
- A retry strategy such as `ExponentialBackOff` helps avoid immediate repeated failures under temporary issues.
- This makes message processing more resilient when external systems are slow or briefly unavailable.

### 3. Configuration through Spring beans
- Spring configuration classes can register beans using `@Configuration` and `@Bean`.
- This keeps Kafka-related settings organized and makes the application easier to extend.
- It also improves readability by separating infrastructure setup from business logic.

### 4. Avro and schema-based message contracts
- Kafka payloads are often safer to manage with schemas rather than sending plain raw objects.
- Avro helps standardize message structure and supports compatibility across versions.
- Schema Registry is useful when multiple services consume the same Kafka topics.

### 5. Learning approach for Kafka
- I learned that practical Kafka learning is not only about publishing messages but also handling retries, failures, serialization, and consumer behavior.
- A good Kafka project must consider delivery guarantees, consumer groups, schema evolution, and operational monitoring.

## Key takeaway
The latest work reinforced that Kafka is not just a message broker; it is a system that requires careful attention to reliability, configuration, and message contract design.
